# 国际象棋训练器（本地版）

纯 Python 写的国际象棋引擎 + 训练工具，**零依赖**，有 Python 3 就能跑。
不联网、不装包，所有计算都在你自己电脑上。

## 快速开始

```bash
cd chess_trainer
python3 trainer.py
```

也可以直接进某个模式：

```bash
python3 trainer.py play              # 对弈
python3 trainer.py advise            # 跟棋助手（你报着法，我给建议）
python3 trainer.py blind             # 盲区训练
python3 trainer.py puzzle            # 战术题
python3 trainer.py drill             # 残局训练 / 转化优势
python3 trainer.py review 我的棋.pgn  # 复盘分析
python3 trainer.py cct                # CCT 扫描练习（将军/吃子/威胁）
python3 trainer.py cct "<FEN>"        # 直接查某个局面的将军/吃子/威胁
python3 trainer.py study              # 实战研究局面（从自己对局挑的判断题）
python3 trainer.py play "<FEN>"       # 从指定局面开打（用来把优势局面转化出来）
```

跟棋 / 对弈里随时能打：`cct`（列出我的将军/吃子/威胁）、`fen`（看当前局面的 FEN）、
`resign`（认输结束，可存谱复盘）、`board` / `moves` / `undo` / `save` / `help`。

棋盘有三档大小，随时在对局里打 `small` / `big` / `huge` 切换，或者启动时指定：

```bash
CHESS_SIZE=huge python3 trainer.py
```

- `small` 一行一格，最紧凑
- `big`（默认）格子画成方框
- `huge` **每个棋子用三行字符拼出来**，图标本身就变大了（白子 `(R)`，黑子 `[r]`，
  顶上那笔是形状提示：王 `\|/`、后 `ooo`、车 `|-|`、象 `^`、马 `/^`、兵 `o`）。
  整个棋盘 33 行，终端窗口要拉高一点

终端字体本身也能放大（macOS 终端按 ⌘ 和 `+`），那个对眼睛的帮助最直接。

如果棋子显示成乱码方块，用 `CHESS_ASCII=1 python3 trainer.py` 换成字母棋盘。

## 按短板练什么（Jeremy 专用对照表）

从他 2026 年这些对局里反复看到的毛病，和对应该练的东西：

| 短板 | 实战例子 | 练哪个 |
|---|---|---|
| **白送子 / 吃子前没算安全**（最集中，占比最高） | Hunter 10.Nxg5 无理弃子；George 18.b4 走进 Nc3 三叉 | `blind` 选第 3 类（谁在白送）；落子前在 `advise` 里打 `cct` 扫一遍 |
| **没扫对方的威胁** | George 18.b4 前没看见 Ne4→c3 | `blind` 选第 2 类（对手的威胁）；`cct` 看「威胁」那行；`study` 第 2 题 |
| **薄优势转化不了**（多一整子他 97% 能收，难在小优势） | George 执白没赢下来；执白 7 胜 6 负，执黑 0 负 | `drill` 末尾三道**小优势**（多交换子 / 残局多一兵）；`play "<FEN>"` 重打自己赢面没赢下来的局面 |
| **找最强杀 / 一步赢子** | George 漏掉 16.Nxe5‼；顺手吃子而非最锋利一击 | `puzzle`（含新加的两道**马叉**「找一步赢子」）；lichess 筛 `mate` / `crushing`；`study` 第 1 题 |
| **残局技术**（车兵收不干净） | elijah 均势残局推成孤兵输掉 | `drill`：卢塞纳、王兵取胜、多子转化 |
| **落子前不算对方最强回应**（总根） | 几乎每盘的失着 | 铁律：吃/将/弃/推兵之前先问「对方最强怎么应、走完我亏不亏」 |

> 原则：**lichess 做题练"找杀"；转化靠 `play`/`drill` 把赢的局面打出来 + 复盘；
> `cct` 是落子前对答案的工具，`study` 是他自己对局的判断题。**
>
> 2026-11 更新：他把"多一整子/一象"的转化题跑出了 97% 准确率——**说明他收干净
> 一个大优势没问题，短板不在残局收官，而在①不明朗时漏算战术/安全，②薄优势
> （多一兵、一交换子）把握不住。** 所以别再练"多一子怎么赢"，劲往这两处砸。

## 六个模式

**1. 对弈** —— 和引擎下棋，随时可以要提示、悔棋、看评分。
开着「实时教练」的话，你每走一步它会立刻打分：

```
你走 Bc5?! —— 略欠精确（更好: Nf6 Nc3 Bb4 Nd5，少丢 45 分）
```

一局结束会给平均每步损失、失误统计和估算准确率。

**2. 跟棋助手** —— 你在别处下棋（网站、手机 App、真人对面），把双方的着法报给它，
轮到你的时候它自动给建议：

```
对方走了什么？: e4

  ▶ 建议走: Nc6      评估 -0.21   (深度 7, 0.8s)
    预计后续: Nc6 Nf3 Nf6 e5 Ne4 Nc3
你实际走了什么？(回车 = 就走建议的那步):
```

**按难度给建议**（启动时那一问，或对局中 `level 4`）：

```
按哪个难度给建议？(1-8，回车 = 满血): 4

  ▶ L4 会走: Qe2      比最佳差 0.06 个兵
  ▶ 最佳是:  Bg5      评估 +0.03（基本均势）   (深度 5, 想了 2.4 秒)
    预计后续: 13.Bg5 h6 14.Be3 Ne4 15.Rfe1
```

**两个都显示，永远看得到正解。** 用途有两个：

- **扮演一个特定水平的对手** —— 你跟学生下棋时，用它生成对方的着法
- **备课** —— 「这个水平的人大概会走哪步、差多少」，一眼就看出来了

`level 0` 回到满血。开局库里的着法不受难度影响（那是公认的理论着法，
没有难不难的问题）。

注意「比最佳差 X 兵」是用**满血搜索**给那一档选的着法打的分，
所以这个差值是可信的，不是那一档自己给自己打的分。

直接按回车就是采纳建议；你也可以走别的，照实报给它就行。常用指令：
`side b` 改成执黑（一开始选错了不用重开）、`top 3` 看前三个候选和分数、
`again` 再想久一点、`think 5` 改成每次想 5 秒、`undo` 收回报错的一步、
`new` 重新开局、`fen <FEN>` 从中局某个局面开始、`save` 存棋谱、
`load games/xxx.pgn` **读入之前存的棋谱接着往下下**。

「预计后续」是**双方轮流走**的主变（带回合数，一眼看得出谁走的），
默认显示 12 层，也就是六个回合。

**主题行（挂 Stockfish 时才有意义）**：引擎不会「想计划」，它只会算着法。所以这一行
不是它的战略思想，而是**把它算出来的前 3 条主变放在一起，找反复出现的东西**：

```
  ▶ 建议走: Re1      评估 -0.02（基本均势）   (深度 31, 想了 1.0 秒)
    预计后续: 13.Re1 Ng4 14.c4 Nxe3 15.fxe3 Qd6 16.Rac1 Rac8 17.c5 bxc5
    主题: 你：重子上 e 线（半开放） · 准备 c4 突破（2/3 条主变）   对方：把 e4 当据点
```

判据全部是死算的，而且**统计类的主题至少要在 2 条主变里同时出现**才报：

- **重子上线** —— 车/后走到一条自己没有兵的直线上（吃子落上去不算）
- **兵的突破** —— 兵**推进**到与对方兵接触的位置（吃子不算，那是执行不是计划）
- **据点** —— 马/象反复落到对方半场的同一个格子，且对方的兵永远够不到
- **压向王翼** —— 两个以上不同的子进入对方王周围两格

找不到可靠主题就**什么都不打印**，不会为了凑一句话而编。`python3 plans.py` 会跑 8 项自检。

不挂 Stockfish 的话，自带引擎没有 MultiPV，只有一条主变，程序会自动收紧判据
（只报那条线里确实发生的兵突破），所以主题会少很多——**这是有意的，不是坏了**。

它想棋的时候屏幕上会滚动显示搜索进度（深度、暂定的着法、已用时间），
所以别在没出现提问的时候提前敲字——提问时会自动清掉抢先输入的内容，免得被当成答案。

**3. 盲区训练** —— 1000-1600 最该练的东西。研究表明这个水平的失误几乎都不是
「算得不够深」，而是**第 1 层就没看**。所以这个模式专练「别漏看」，三种题：

- **将军与吃子清单**：把你现在能走的所有将军和吃子一个不落地列出来，程序对答案
- **对手的威胁**：假设你这一手白白让掉，对手会走哪一步（空着搜索算标准答案）。
  只会出「真有威胁」的局面——不管的话至少要亏 1.5 个兵，否则这题没意义。
  如果答案是「把某个子撤走」，会额外点明：那个子现在正被你攻击，
  所谓威胁其实是对方要救它，**也就是你现在能直接吃**
- **谁在白送**：哪些子现在能被白吃（用静态兑子 SEE 判定，有保护的不算）。
  答案会附一行「为什么」：被谁攻击、有没有保护、吃了净赚多少

```
———— 第 3/8 题 · 谁在白送 ————
  轮到白方走。
  哪些格子上的子现在能被白吃？（写格子名，空格隔开；没有就打「无」）
  你的答案: e5 c4
  正确答案: e5(黑方的子，值 320 分)
  ✗ 多写: c4
```

答题时可以打 `fen` 看局面串、`help` 再看一遍题目要求、`skip` 跳过。

**判卷用的是引擎，而引擎只有 ~1230 的水平。** 「对手的威胁」这类题接受
「跟最佳差 0.6 兵以内」的答案，答错时会把你那步的分数一起打出来：

```
  Your Rd5 scores +0.40 — 1.8 pawns below best.
  (Within 0.6 counts as correct. This judge plays at ~1230,
   so treat close calls with suspicion.)
```

也就是说，**差距小的时候别全信它**——尤其是先手、抢先手这类靠节奏取胜的着法，
弱引擎最容易低估。装了 Stockfish 的话，让它当判官会准得多：

```bash
CHESS_ENGINE=sf python3 trainer.py blind en
```

**英文出题**（教英文学生用）：

```bash
python3 trainer.py blind en        # 或 CHESS_LANG=en python3 trainer.py blind
```

题目、提示、判卷结果全套英文，棋盘和记谱本来就是国际通用的：

```
———— Drill 2/8 · Checks & captures ————
  Task: Black to move. List **every** capture and check Black can play
  right now — miss none (write them like Nxe5, Qh5+).
  Your answer (fen = show FEN / skip): Nxc3 Qxa2
  Answer (6 total): Nxc3  Nxf2  Nxg3  Qxa2  Qxc3  bxc4
  ✗ Missed: Nxf2  Nxg3  Qxc3  bxc4
```

**局面默认就从 `games/` 里的全部棋谱取**——你存过的每一盘都会被用上，
按 FEN 去重，`_` 开头的内部文件（_autosave 之类）自动跳过：

```
局面从哪来？(回车 = games/ 里的全部棋谱；gen = 自动生成；也可以输入文件名或学生名字):
  从 games 的 7 个棋谱里取到 24 个局面。
    Jvpaul.pgn                       54
    game_20260810_d4.pgn             64
    gianna.pgn                       60
    ...
```

那一问有四种填法：

| 填什么 | 用什么局面 |
|---|---|
| **回车** | `games/` 里的全部棋谱（默认，最有针对性） |
| `gen` | 自动生成（自对弈随机局面） |
| 文件名 | 只用那一个棋谱 |
| **学生名字** | 文件名里含这几个字的全部棋谱，比如打 `jv` 就只用 Jeremy 那几盘 |

**用他自己下过的棋来练，测出来的才是他真实的盲区，不是随机局面。**

**出过的题会记下来，下次优先出没练过的**：

```
  还没练过的局面：453 / 459 个。
```

记录存在 `games/students/_seen_<来源>.txt`（纯文本，一行一个 FEN），
**按来源分开记**——打 `jv` 练的和打回车练的各记各的，不会互相干扰。
一轮全练完会提示「全部 N 个局面都练过一遍了」然后自动重置，开始第 2 轮。

（自动生成的局面不记进去，只记真的来自棋谱的。）

**4. 战术题** —— 14 道题，底线杀、闷杀、马双叉、串击等。
答案不是死记的：你走完之后引擎会重新算一遍局面，只要你的着法效果不比最佳差
40 分以内就算对，所以有多解的题目不会被判错。卡住可以输 `hint` 或 `solution`。

**5. 残局训练 / 转化优势** —— 14 个局面：基本杀法（单车/单后杀王）、取胜技术
（卢塞纳、王兵取胜）、守和（王兵对王、正面挡兵），外加一组**转化优势**题
（执白多一马 / 多一象 / 多一交换子，对着引擎下到赢）。每个都标好目标（取胜 / 守和），
你执一方跟引擎下到分出结果，最后告诉你有没有达成。想把**自己**赢面没赢下来的局面
重打，用 `python3 trainer.py play "<FEN>"` 从那个局面开打。

**6. 复盘分析** —— 粘贴 PGN 或着法（也可以读文件），逐步分析：

```
手数    方    实战       评价         评分      引擎建议
28    黑    Qe6??    严重失误(-542) +8.70   Qc5 Bxd7+ Ke7 Qf3
29    白    Bxd7+!   最佳         +8.70
...
白方: 平均损失 15 分 · 失误 2 · 严重失误 0 · 估算准确率 94%
```

报告末尾还有一段**结构诊断**——不花引擎时间，全是数出来的：

```
———— 结构诊断（子力好不好用，纯数出来的，没用引擎）————
「最差的子」= 已经出动过的子里，活动格数最少的那个。
  白方 全程平均 4.4 个落点 · 黑方 全程平均 1.6 个落点
  黑方：第 12 回合 Bb7(3 个落点) 一路掉到 第 20 回合 Ba8(0)，中间没回升过。
  第 17 回合 黑 Rb7? → 最差的子 Ba8 的活动格数 2 → 0 · Ba8 一步都走不了
```

这一段是为了回答「一个子都没丢，怎么就输了」。评分说「Bb7 丢了 0.95 分」
没法教，「你的象从 6 个落点掉到 0」可以直接教。四类说明：

- **最差的子变得更差** —— 活动格数一步之内掉 2 以上，或者跌到 3 以下
- **一步都走不了** —— 只在刚被封死的那一步报一次，不重复刷屏
- **让出了某条线** —— 你的车/后原来占着一条自己没兵的线，现在不占了
- **象走到了自己兵的颜色上** —— 同色格上有 4 个以上自己的兵

几条刻意的约束，都是拿真实对局调出来的：

- **只看已经出动过的子。** 开局没动的车当然 0 个落点，那是常态不是毛病。
  出动与否是**跟着棋子**记的，不是看「在不在原位」——那盘 QGD 里黑象最后
  停在 a8（车的出发格），只看格子会漏掉
- **说明只挂在已经被判为失误的着法上**，不是每步都唠叨
- **「持续走低」至少要横跨 4 步**才报，否则只是收官时的正常波动
- 「占住了某条线」不报——那不是毛病

`python3 structure.py` 会跑 12 项自检。

复盘完会问一句「记进哪个学生的档案？」——填了名字就往 `games/students/<名字>.csv`
里追加一行，并把趋势打出来：

```
———— Jeremy 的档案（5 盘）————
日期          执   步数   严重失误   每N步崩   结果
2026-08-08  白   21    3       7.0     0-1
2026-08-09  白   31    2       15.5    0-1
...
全部 5 盘：每 7.9 步一次严重失误
最近 3 盘：每 9.2 步一次   之前 3 盘：每 7.5 步一次   在变好 ↑

失误类型（共打了 26 个标签）：
  白送子                    8  ██████
  漏掉一步白吃                 8  ██████
  ...
最集中的一类是「白送子」，占 31%——先练这个。
```

**胜负已定之后的丢分不计入统计。** 走之前和走之后都超过 ±5 兵（同号）的着法，
在表里标成 `严重失误·已定`，但不进统计——「+19 掉到 +17」和「把 5 步杀走成
10 步杀」都不影响结果，混进来会污染「每 N 步崩一次」这个主指标。
统计行末尾会写「另有 N 步严重丢分发生在胜负已定之后，未计入」。

**为什么盯「每 N 步崩一次」而不是等级分**：等级分是滞后指标，错误率已经在降了，
分数可能两个月都不动，中间很容易误判成「白教了」。这个数字 4-8 周就能看出变化。
（「平均损失」不适合跨报告比——它依赖用哪个引擎、每步想几秒。严重失误是 5 个兵
量级的错，哪台引擎都认得出来。）

失误分类全部是机械判定的，`python3 errors.py` 会拿三个真实对局里的着法验证：

| 标签 | 判据 |
|---|---|
| 白送子 | 走完之后自己多了一个 SEE 判定白送的子 |
| 走开的子原来在守它 | 被移动的子，走之前正是那个子的保护者 |
| 挪开挡线的子 | 被移动的子，原来挡在对方远程子和自己大子之间 |
| 漏掉一步白吃 | 引擎的最佳着法是一步白赚的吃子，实战没吃 |
| 贪兵 | 这一步用子吃了个兵 |

随时可以单独看：`python3 profile_log.py Jeremy`

**改完代码跑一下冒烟测试**：`python3 test_smoke.py`（几秒）。它会真的跑一遍复盘、
学生档案、跟棋建议、盲区取局面这几条主路径——`import trainer` 只查语法，
函数体里的问题要真跑才发现（改 `make_engine` 时误删过 `is_decided`，
导入照样通过，复盘跑到一半才炸）。

报告会自动存成 `games/review_日期.txt`。

### 棋谱不会丢

- **每走一步**都往 `games/_autosave.pgn` 写一份快照。中途关窗口、断电、程序崩了，
  这份都在，`load` 进去就能接着下
- **棋局结束时自动存**成 `games/game_日期_时间.pgn`，不问你要不要——问了就有丢的风险
- 结束后会问要不要马上复盘，报告存到 `games/review_日期.txt`
- 想自己命名随时 `save 名字`

**所有棋谱和报告都在 `games/` 子目录里**，跟代码分开放。
想换地方就 `CHESS_GAMES=/你的/路径 python3 trainer.py`。

## 评估分数怎么读

界面上的 `+0.70` 这类数字，**单位是「兵」**：+0.70 就是「好上大约 0.7 个兵」。
正负是站在**该走棋一方**的角度（轮到你时，正数就是对你有利）。

| 分数 | 含义 |
|---|---|
| 0.00 ± 0.25 | 基本均势 |
| ±0.3 ~ 0.8 | 略优 |
| ±0.8 ~ 1.6 | 占优 |
| ±1.6 ~ 3.0 | 明显占优 |
| ±3.0 以上 | 大优（相当于多一个马/象，通常已定胜负） |
| ±5.0 以上 | 相当于多一个车 |
| `#3` / `#-2` | 三步内将杀 / 两步内被将杀 |

数字旁边会直接写成人话，比如 `+0.65（白方略优 0.7 个兵）`，不用自己换算。
「深度 11」是往后算了 11 层；「预计后续」是它认为双方都走最好时的走法。

注意这是**这台引擎的看法**，不是绝对真理——它的评估函数很简单，
0.3 以内的差距基本属于噪声，不必当真。

## 开局库

引擎自己算开局是不靠谱的——1.e4 之后 e5 / Nc6 / Nf6 在它眼里只差 2 个百分之一兵，
纯属噪声。所以前十几步改成走 `book.py` 里的**主流理论**：

- 45 条主变、463 个局面，覆盖意大利、西班牙、苏格兰、俄罗斯防御、王翼弃兵、
  西西里（那道夫/龙式/斯维什尼科夫/加速龙/泰马诺夫/罗索里莫/阿拉平）、
  法兰西（古典/维纳维尔/塔拉什/进兵）、卡罗-卡恩、皮尔茨、阿廖欣、中心反击、
  后翼弃兵、斯拉夫、半斯拉夫、尼姆佐/后翼/王翼印度、格林菲尔德、加泰罗尼亚、
  贝诺尼、伦敦体系、荷兰、英国式、列蒂等
- 库里有多条线经过同一局面时会随机挑一条，所以每盘开局不会一模一样
- 界面会告诉你现在走的是哪个开局（「开局库：西班牙开局」）
- 对弈时你走出理论着法，教练不会判你失误，会标「开局理论」
- 跟棋助手里想让引擎自己算而不用库，打 `again`

`python3 test_book.py` 会逐步重放每条线验证合法性，并让引擎检查每条线终局面的
评估是否在合理范围（±2 兵）内——手抄错一步基本都会被这一关拦下。

出了库（对手走冷门变例、或者理论线走完了）就自动切回引擎搜索。库很小，
所以别指望它有深厚的开局理论，它的作用是**别在开局阶段给你瞎出主意**。

## 难度

**这里不标等级分。** 因为没有跟任何有等级分的对手实测过，标 USCF / FIDE /
chess.com 的数字都是编的。下面写的都是可以直接从 `engine.py` 的 `LEVELS`
里对照验证的事实：

| 等级 | 搜索深度 | 每步用时 | 随机噪声 | 故意走坏的概率 |
|---|---|---|---|---|
| 1 | 1 层 | 0.05 秒 | ±150 | 30% |
| 2 | 2 层 | 0.1 秒 | ±110 | 20% |
| 3 | 2 层 | 0.2 秒 | ±80 | 12% |
| 4 | 3 层 | 0.35 秒 | ±55 | 7% |
| 5 | 4 层 | 0.6 秒 | ±35 | 4% |
| 6 | 5 层 | 1 秒 | ±22 | 2% |
| 7 | 6 层 | 1.5 秒 | ±12 | 0 |
| 8 | 8 层 | 2.5 秒 | ±5 | 0 |
| 9 | 不限 | 5 秒 | 0 | 0 |
| 10 | 不限 | 10 秒 | 0 | 0 |

「噪声」是给每个候选着法的评分加一个随机数再挑最高的，单位是百分之一兵；
「故意走坏」是直接从第 2-5 名里随机选一个。两者都只影响非杀棋局面——
**任何等级下，只要引擎算到了杀棋就一定会走**。

### 已实测的一档

**L5 ≈ 1230 分（CCRL 40/4 尺度，95% 区间约 1080 ~ 1375）。**
用 `calibrate.py` 跟限定强度的 Stockfish 18 各下 20 盘，两轮独立测量：

| 对手 | 战绩 | 得分率 | 推算 | 95% 区间 |
|---|---|---|---|---|
| Stockfish@1500 | 4胜 0和 16负 | 20% | 1259 | 861 ~ 1411 |
| Stockfish@1320 | 7胜 0和 13负 | 35% | 1212 | 1006 ~ 1361 |

两轮结果只差 47 分、互相落在对方区间内，测量是稳的。按误差加权合并得 ≈1230。

两点让这个数字**偏乐观**，真实值可能更低：

1. 1320 是 Stockfish `UCI_Elo` 的下限。在它最弱的设置下本引擎才拿到 35%，
   说明它比 Stockfish 能调到的最弱状态还弱，1230 是往下外推的，没有直接对照点。
2. 测试用的是默认 1 秒/步，低于 Stockfish 标定用的 120s+1s，这个偏差也偏向被测方。

其余等级没测过。参照 L5 的实测值，之前那些「L4≈1200 / L6≈1600」的估计整体
偏高约 150-200 分。想测别的档：`python3 calibrate.py --level 7 --auto`
（每档约 20-25 分钟）。

单调性是确认过的：L5 执黑执白都赢了 L2。最实用的判断标准仍然是自己下——
从 L5 开始，赢得轻松就往上调。

## 接 Stockfish（可选）

自带引擎大约 5 万节点/秒、10 秒搜 8-9 层；Stockfish 每秒几千万节点、同样时间能到
30 层以上，CCRL 单核等级分 3653。差距是一千多分，不是一个量级的东西。

```bash
brew install stockfish          # macOS
python3 uci.py                  # 确认能找到、能跑
```

**装上就自动用了，不用设任何环境变量。** 复盘、盲区训练判卷、跟棋建议全部走
Stockfish；找不到的话会打一行提示然后回退到自带引擎。

**例外是 `play` 和 `advise` 这两个模式**——它们都会用到难度档
（`engine.LEVELS`），而难度档是拿自带引擎标定的，换成 Stockfish 之后同一档明显
更强，跟实测的数字对不上。这两处默认用自带引擎，要 Stockfish 就显式设
`CHESS_ENGINE=sf`。

要强制的话：

| | 效果 |
|---|---|
| `CHESS_ENGINE=sf` | 所有地方都用 Stockfish，**包括对弈和跟棋** |
| `CHESS_ENGINE=builtin` | 所有地方都用自带引擎 |
| `CHESS_SF=/路径/stockfish` | 指定可执行文件的位置 |

复盘报告的头两行会写清楚这一份是谁判的：

```
复盘报告  (2026-08-11 14:17)
分析引擎: Stockfish 18 · 每步 0.6 秒
```

**不同引擎跑出来的数字不能混着比**，所以这一行很重要——学生档案里的
「每 N 步崩一次」只有在同一把尺子下才有意义。

### 量一量自带引擎到底多少分

`calibrate.py` 拿 Stockfish 的 `UCI_Elo` 当尺子：让本引擎的某一级跟限定强度的
Stockfish 下 N 盘（轮流执先、开局库随机开局、用 Stockfish 的评估做裁决），
按得分率反推分差 `d = -400·log10(1/p - 1)`。

```bash
python3 calibrate.py --level 5 --auto        # 自动找合适的对手强度
python3 calibrate.py --level 5 --elo 1500 --games 20
python3 calibrate.py --all                   # 1-8 级全测，很慢
```

输出会带 95% 置信区间。

**量出来的是 CCRL 40/4 尺度的分，不是 USCF，也不是 FIDE。** Stockfish 官方文档原话：
UCI_Elo "has been calibrated at a time control of 120s+1s and anchored to CCRL 40/4"。
CCRL 是引擎之间对下形成的分数池，跟人类等级分之间没有官方换算，网上那些对照表都是民间估的。

另外三点：

- 它是按 **120秒+1秒** 标定的。`--sf-time` 给得越少，Stockfish 越弱于标称分，
  结果就越偏向被测方。默认 1 秒其实已经偏少，想准就 `--sf-time 2` 以上（很慢）。
- 20 盘的统计误差 ±100 分起步。
- 换机器、换时控，结果都会变。

但**这是测出来的，不是编的**——跑完把数字填回上面那张表，并注明是 CCRL 尺度。

### 这部分是怎么测的

我写这些代码时机器上没有 Stockfish（沙箱装不了），所以另写了一个 `fake_uci.py`：
用本项目的引擎伪装成一个 UCI 引擎。`test_uci.py` 会启动一个**真的子进程**、
走**真的管道**、解析**真的 info/bestmove**，检查着法合法性、主变可连续走、
将杀分数换算、MultiPV、任意 FEN 起始、连续对弈十几步不出错。

所以：协议层是完整测过的；**Stockfish 特有的选项名**（`UCI_LimitStrength`、
`UCI_Elo`、`Skill Level`）是照官方文档写的，没在真 Stockfish 上验证过。
你装完跑一次 `python3 uci.py`，一秒就知道对不对。

## 引擎是怎么做的

- **棋盘**：0x88 表示法，完整支持王车易位、吃过路兵、升变、三次重复、50 回合规则
- **搜索**：迭代加深 + Alpha-Beta + 主要变例搜索、置换表（Zobrist 哈希）、
  静态搜索、空着裁剪、后期着法缩减、杀手着法与历史启发、将军延伸
- **评估**：子力 + 棋子位置表（残局/中局插值）、双象、兵形（叠兵/孤兵/通路兵）、
  车占开放线、残局逼王到角落
- **速度**：约 5 万节点/秒（纯 Python），2 秒能搜到 8 层左右

## 正确性验证

这套代码经过了这些测试，都能自己复跑：

```bash
python3 test_perft.py 250000    # 着法生成（快，约 2 秒）
python3 test_perft.py 5000000   # 完整版，约 40 秒
python3 test_selfplay.py        # 自动对弈 + 复盘流程，约 40 秒
python3 test_book.py            # 开局库每条线的合法性 + 评估检查
python3 test_uci.py             # UCI 适配层（没装 Stockfish 也能测）
python3 test_blindspot.py       # SEE 等盲区计算（对照公开的 SEE 标准值）
python3 puzzles.py              # 用引擎逐条验证题库答案
```

- **perft**：6 个标准测试局面（初始局面、Kiwipete 等）全部对上公开的标准节点数，
  最深到 4,865,609 个节点，一个不差
- **自动对弈**：三盘自动对局，每一步都检查棋盘栈、着法记录、回合数是否同步，
  棋谱重放后局面必须完全一致；另外检查悔棋、评估函数的黑白对称性
- **静态兑子(SEE)**：在经典子力值下能精确复现 chessprogramming wiki 上公布的
  两个标准测试值（+100 和 -200）；判卷逻辑也用已知答案喂进去测过
- **题库**：14 道战术题和 9 个残局全部由引擎验证过——杀棋题必须真的能将杀，
  得子题最佳着法必须比次优着好 250 分以上，残局的「取胜/守和」标注也是算出来的

开发过程中这套测试抓到了一个真实的 bug：空着搜索用 `finally` 撤销时，
一旦搜索超时会误弹出一步真实着法，导致棋盘被悄悄破坏（约 1% 概率）。现已修复。
